# Repeatable research protocol — version 1

Run these passes in order for every new offer. Use the user's business, buyer,
service, geography and language in the same query families. Search current
sources; retain older conceptual material when relevant and label its date.
No score or source count establishes truth. Targets below bound effort rather
than license filler. Stop each pass when its useful coverage target is met or
two materially different searches yield no new usable evidence. Record gaps.

| Pass | Action and query families | Useful coverage target |
| --- | --- | --- |
| 1. Business | Read supplied website's service, about, proof/case and pricing pages where available. Search `[business] [service]`. | Actual service, claim, scope and proof inventory from up to 4 relevant pages. |
| 2. Alternatives | Search `[service] for [buyer] [market]`, `[service] pricing retainer`, and `[buyer problem] alternatives`. Open provider pages. Include in-house, delay or DIY as hypotheses unless evidenced. | 3 relevant alternatives with buyer, promise, mechanism, terms, public price/date or “not disclosed,” proof and gaps. |
| 3. Buyer demand | Search `[buyer role] [problem] challenges`, `[problem] review experience`, and `[service] objections`. Use attributable buyer discussions, reviews or interviews; read originals when accessible. | 3 useful buyer observations from at least 2 independent sources, or an explicit evidence gap. Vendor claims are not buyer testimony. |
| 4. LinkedIn | Search `site:linkedin.com/posts [service] [buyer problem]` and `site:linkedin.com [service] offer retainer pricing`. Use originals; exclude AI topic pages. | Up to 2 substantive posts/articles relevant to this buyer or offer design. |
| 5. X | Search `site:x.com [service] offer`, `site:x.com [buyer problem]` and `site:x.com professional services retainer guarantee`. Use available native search only if access is already available. | Up to 2 substantive original posts. Do not require account login or bypass restrictions. |
| 6. YouTube | Search `site:youtube.com/watch [service] [buyer problem]` and `site:youtube.com/watch professional services offer pricing retainer`. | Up to 2 relevant videos with accessible transcripts. Read captions before claiming spoken content; metadata alone is discovery, not evidence. |
| 7. Synthesis | Compare with the bundled method reference; seek one counterexample or delivery constraint for the proposed direction. | Opportunity, buyer language, sameness to avoid, plausible differentiator, proof gaps, scope risk and questions to resolve. |

If a source is blocked, try one accessible original alternative. A publisher's
article can support the same concept, but is not proof the blocked video/post
was read. Avoid repeated access loops. No fixed claim of an exhaustive scan.
Do not bulk copy transcripts or paywalled material into the result.

Maintain this receipt in the conversation working brief and result appendix:

- Protocol version, research date and business/buyer/market scope.
- Queries attempted by pass; pass state: complete, partial, inaccessible or not
  applicable, with reason. Every social/video pass is attempted when web exists.
- Source ID, title/author, direct URL, publication date if known, access date,
  type (business claim / buyer observation / practitioner method), access depth
  (full text / captions / excerpt / discovery only), supported finding and limit.
- Key claims linked to source IDs. Distinguish observed facts, user statements,
  hypotheses and recommendations. Search snippets remain partial evidence.
- Unresolved gaps and the questions/interviews needed to close them.

Deduplicate syndicated copies. Separate a competitor's promise from verified
performance. Quote sparingly and accurately. Public evidence cannot establish
the user's delivery costs, pricing approval, client permissions or capacity.
