# Security reports

Report suspected credentials, unsafe archive handling, cross-consumer access, or
signature/receipt bypass privately to the repository owner using an existing
authorized contact channel. Do not include live secrets, member records, or
private customer data in issues, PRs, logs or screenshots. If a private reporting
channel is unavailable, ask the owner for one before sharing sensitive details.

Include a sanitized reproduction, affected commit/release, expected boundary and
observed behavior. Owners handle credential revocation and signing-key response
under the release trust contract. An automated content scan does not establish
that Git history or third-party provenance is cleared for distribution.
