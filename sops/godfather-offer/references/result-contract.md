# Offer result and document delivery

Create a clean editable document titled “[Business] — [Offer name]”, dated using
the user's timezone. The first page should make the offer understandable without
reading the appendix. Use concise prose, real heading styles and readable tables.
Keep internal economics and unresolved claims separate from buyer-facing copy.

Required content (omit empty decoration, retain explicit material unknowns):

1. **Offer at a glance:** buyer/trigger, promise, controlled commitment, mechanism,
   first milestone, timeframe, proposed fee and next step. Label draft status.
2. **Why this offer:** research-backed opportunity and chosen structure, with
   concise citations. Distinguish evidence from judgment.
3. **Scope and terms:** inclusions, exclusions, acceptance, responsibilities,
   capacity/change rules, risk reversal and genuine urgency if supported.
   Retainers include recurring value, cadence, response, setup and exit terms.
4. **Direct-response draft:** opening/ad, landing-page promise and supporting
   points, proof placeholders, CTA, qualification questions and proposal outline.
   Terms must agree across all assets; no unverified proof disguised as copy.
5. **Internal economics:** currency/period, supplied assumptions, contribution,
   margin, downside and retainer setup if relevant. Unknowns visibly unknown.
6. **Test and decisions:** a practical pilot, measures, stop rule and unresolved
   evidence/owner decisions. Do not imply approval or market validation.
7. **Research appendix:** compact source register, access limits, protocol/date,
   queries/coverage and claim links. Include only useful excerpts, not raw captures.

## Host delivery

Use the host's available native editable document/artifact tool, following its
current schema and document skill when available. Do not assume a tool name,
a particular artifact surface, a menu location or a Word export capability. A skill adds
instructions; it cannot enable missing host tools.

Prefer an editable artifact with native .docx export. If native Word export is
unavailable but file generation exists, create a real .docx containing the same
final content and attach it with the editable artifact. Use supported document
libraries/tools, real headings and tables, working source hyperlinks and no
macros. Read back the artifact; if creating .docx, verify it opens structurally and
contains the expected sections, values and sources before linking it. Maintain
content parity after edits; export the latest document, not an earlier draft.
Do not silently create a third-party Drive/Notion destination.

If neither document nor file generation is available, provide the full formatted
result in chat and clearly say downloadable document delivery is unavailable in
this environment. Do not fabricate a download link. This is a delivery limitation,
not a reason to withhold the useful offer.

Final response: “Here's your result” + actual artifact link/attachment. Add a short
Word-download note only when supported. No future-form/workshop question, mode
selection, sales pitch or unrelated follow-up. The result remains editable by
ordinary follow-up requests.
