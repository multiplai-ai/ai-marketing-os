# Page brief contract

Read when drafting a full consultation page or preparing its build handoff.
This is an original working format. Adjust sections to the evidence and scope;
it is not the tutorial's exact sequence or a mandatory copywriting formula.

## Decision record

Record the business/service, audience, traffic promise, awareness assumption,
conversion action, chosen angle and evidence IDs, consultation terms, paid
offer boundary, voice sources and research status. Separate owner decisions
from missing research or unavailable technical checks so the next action is
clear. State where the artifact will live in the consumer's workspace.

## Page draft

Provide visitor-facing copy in reading order, with concise build notes outside
it. Useful blocks to consider are:

| Block | Draft / handoff requirement |
| --- | --- |
| First screen | Audience, concrete reason to continue, primary CTA and approved supporting evidence. Specify intended mobile order; optional media needs a real asset or a marked production task. |
| Decision context | The buyer situation that the evidence actually describes, including relevant qualifications. |
| Service explanation | What happens and why it addresses that situation; scope, dependencies and limits. |
| Evidence | Approved claims and proof placement; omit missing testimonials rather than fabricate people or results. |
| Consultation | Exact deliverable, attendee fit, preparation and approved terms, without conflating it with the paid engagement. |
| Questions | Answers to sourced buyer uncertainties. Label inferred questions in the editorial notes. |
| Booking and follow-through | CTA destination, necessary fields, next-step text and confirmed operational handoff. Unknown behavior is a build task. |

Every block does not need its own section. Do not use bracketed internal holds
as finished visitor copy. If a section cannot be drafted honestly, explain the
gap separately and supply the portions supported by evidence.

## Evidence and readiness record

Use a compact table: copy/claim ID; wording; evidence locator; evidence type
(business fact, buyer observation, inference); approval/permission status;
limitation/action. Do not attach private raw recordings or personal customer
data to a public build brief. A permissioned source locator is sufficient.

List design assets by available/planned status and record checks as performed,
failed or unavailable. Include actual viewport sizes and observed results only
when a rendered page was checked. Copy-only output should say that runtime
checks remain unperformed. Show proposed experiments separately from approved
execution and keep exact-prompt fidelity pending when source text is absent.
